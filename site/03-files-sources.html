3. Files, sources and data dictionaries

Every input the build reads, where it came from, and every variable in the final tables

The database is built from 25 sources. Every file the build reads is frozen on Amazon S3 with a SHA-256 checksum, so the published tables can be rebuilt exactly even after a publisher revises or removes a file: 1,215 files, 32.8 GB. Part 4 shows how to restore them. Each source folder in inputs/ has a SOURCE.md with the publisher, URL, years, how the file is obtained, the build steps that read it, the licence and the citation.

Sources

Why frozen records the reason each source is archived rather than only downloaded on demand:

  • archive needed: not reliably available online. The file was placed by hand, is behind a login, was shared with us, or has no recorded download URL.
  • on demand (release): a fixed public release that a script downloads. It is frozen as a safeguard.
  • on demand (moving): a public file that the publisher revises in place, so a later download can differ.

Licences and redistribution

Federal sources are public domain. NCCS data are under the Open Data Commons Attribution License (ODC-BY 1.0), PatentsView under CC BY 4.0, the MEDSL election returns under CC0 and the McGovern election files under the MIT License. Two sources have no open licence: the Religious Congregations and Membership Study (ASARB) and the NERCRD social capital index. We received permission to redistribute both, and each frozen folder carries a PERMISSION.md.

Frozen-file manifest

Frozen inputs live at s3://lecy/nonprofit-density/inputs/<folder>/. Each folder holds the files, a MANIFEST.csv (path, bytes, SHA-256, original path, the build steps that read the file, freeze date) and the SOURCE.md. The full list of files with checksums is in frozen_manifest.csv.

soi and nccs-bmf (the unified BMF) were frozen before the others and keep their own layout. env/restore_inputs.R handles both.

Final tables

The build produces two analysis tables, one per geographic unit. Both are annual, 2000–2024.

Table Unit Rows Columns
data/analysis/county_year.parquet 3,144 counties (2023 delineation, Connecticut planning regions) 78,600 354
data/analysis/cbsa_year.parquet 925 core-based statistical areas: 387 metropolitan, 538 micropolitan (Office of Management and Budget, 2023) 23,125 422

Covariates observed only in some years come with up to three companions: _obs (a flag, TRUE where the value was observed that year), _lin (linear interpolation between observed years) and _locf (last observation carried forward). The dictionary marks these with gap-fill.

Research guides

Each research frame has a research guide: a profile of every variable, with its definition, data type, summary statistics, a preview of values, and a graphic suited to its type. The guides are built with datagoodr (Beck & Lecy, 2026) from the frames as released in data/.

  • CBSA-year research guide: 925 CBSAs × 25 years, 422 variables.
  • County-year research guide: 3,144 county-equivalents × 25 years, 354 variables.

How they are built. Each guide is driven by a Data Governance File (DGF), one row per variable, in docs/research-guide/<frame>/DGF.xlsx:

  1. docs/make_research_guides.R profiles each frame with create_dgf(). It fills each variable’s label and definition from the variable dictionary below. Gap-fill companions get their base variable’s definition plus a note on the companion.
  2. docs/check_research_guide_types.R checks the data type datagoodr guessed for every variable against the variable’s storage type, its values and its role in the dictionary, and corrects wrong guesses with retype_dgf():
    • geographic codes stay text identifiers, so leading zeros survive;
    • year is temporal;
    • 0/1 flags are boolean;
    • other numeric columns are numbers.
    The script stops if any variable still carries an unexpected type, then validates the DGF with inspect_dgf(). Each frame’s type_review.csv lists the guessed, expected and final type of every variable.
  3. docs/render_research_guides.R renders each guide with create_rg() and copies it here.

Some columns are identical by construction. For example, race_den (the sum of the seven race and ethnicity groups) and pop_total both equal population. The guides note each one in its definition, and duplicates.csv lists them.

Software

The build runs in R (R Core Team, 2026) with package versions pinned by renv (Ushey & Wickham, 2026). It uses data.table (Barrett et al., 2026) and arrow (Richardson et al., 2026) for data handling and fixest (Bergé, 2026) for the panel models. This site is built with Quarto (Allaire et al., 2025).
